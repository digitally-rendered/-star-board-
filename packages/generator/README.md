# @star-board/generator

L4. `FeatureModel` → files: types, zod validators, a typed client, action hooks, default screens,
the registry, routes, navigation and i18n defaults; a pure `generate()` and a drift `check()`.
Depends on `@star-board/core` and `@star-board/spec` only; never imports React, a renderer or a
runtime (ESLint boundaries and `pnpm check:arch` enforce it). The generated _text_ imports
`@star-board/runtime`, `@star-board/core`, `react`, `react-router`, `zod` and the renderer named
in `renderer` (default `@star-board/renderer-mui`).

## Public API

```ts
import {
  plan,
  generate,
  writeFiles,
  check,
  assertNoDrift,
  BUILD_VERSION,
} from '@star-board/generator';

const files = generate(model, { out: 'src/generated', features: 'src/features' });
writeFiles(files, { out: 'src/generated', features: 'src/features' });
check(model, opts); // Drift[]: [{ path, kind: 'missing' | 'changed' | 'extra' }]
```

| Function                            | Role                                                                                                                                                                                                                                                                               |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `plan(model)`                       | Per schema: fields (contract key via core `fieldKeyFor`, order from `x-ui-order` then schema order, group, hidden, help from `x-<field>-reason` or `description`), screens, actions, list and view columns; routes, nav (by schema name) and the i18n defaults. Pure, snapshotted. |
| `generate(model, opts)`             | Pure: `GeneratedFile[]` (`{ path, contents }`) under `opts.out`, sorted by path, LF, one trailing newline, headed `// GENERATED by @star-board/generator <version> from <title>@<version> — do not edit`; `manifest.json` last with a sha256 per file.                             |
| `writeFiles(files, opts)`           | Writes under `out` only. Checks every path first and throws `GeneratorError('GENERATOR_OUT_OF_SURFACE')` if one escapes `out` or lands inside `features`, writing nothing. Never creates, modifies or deletes anything under `features`.                                           |
| `check(model, opts, disk?)`         | Regenerates in memory and compares with disk: `missing`, `changed`, `extra` (a file under `out` the generator did not emit). `disk` is `{ readFile, listFiles? }` or a bare `readFile`; `nodeDisk` is the default.                                                                 |
| `assertNoDrift(model, opts, disk?)` | Throws `GeneratorError('GENERATOR_DRIFT')` with `details.drifts`; the CLI maps it to exit 1 (`codegen:check`).                                                                                                                                                                     |
| `tsType(schema)`, `zodExpr(schema)` | The JSON Schema → TypeScript and → zod 4 emitters, exported for the parity suite.                                                                                                                                                                                                  |

`GenerateOptions`: `out`, `features`, `renderer?` (default `@star-board/renderer-mui`), `i18n?`
(default `true`; `false` drops `i18n.defaults.json` and inlines the defaults in `i18n.ts`).

## Outputs (hexagonal-rules typescript/12 §2 and §5)

```
<out>/
├── domain/                               props-only components; never fetch (typescript/01 §2)
│   ├── contract.ts                       re-exports the renderer's prop contracts (FieldProps, CellProps, ColumnDescriptor, ActionProps, StateProps, HelpProps, Option, FieldDescriptor, UnsavedChangesDialogProps) and adds ScreenStatus, ColumnSpec, TableProps (with `compact`), AgentSlotProps, `useResolved(key, schema, target)`, `useOptionalResolved` (null instead of a RegistryError), `cardFields` and the exactOptionalPropertyTypes helpers (fieldText, stateProps, retryAction)
│   ├── AgentPanelSlot.tsx                the agent affordance slot (screen.custom / agent-panel): passes operationId, args, ifMatch, onApplied, disabled to the renderer's AgentPanel
│   └── <schema>/
│       ├── types.ts                      <Schema>, <Schema>Create, <Schema>Update, branded <Schema>Id, one Pick row type per view
│       ├── schemas.ts                    zod 4: <Schema>CreateSchema, <Schema>UpdateSchema, <Schema>DocumentSchema (+ inferred *Values)
│       ├── columns.ts                    <SCHEMA>_COLUMNS (one ColumnDescriptor per Document field, `list.column.<type>` from the tokens column types: string, number, boolean, date-time, enum, reference), <SCHEMA>_LIST_COLUMNS, one <VIEW>_COLUMNS per view, <SCHEMA>_<FIELD>_OPTIONS for every enum
│       ├── <Schema>ListScreen.tsx        screen.list   — columns from the Document (system fields hidden), sort headers, pager; `compact` renders a card list (first three shown columns, the open action) under the same page-object ids with data-layout="cards"
│       ├── <Schema>GridScreen.tsx        screen.grid   — one per schema with a view; columns and filters from x-view; same compact body
│       ├── <Schema>DetailScreen.tsx      screen.detail — field values through list.column.<type>, help.inline, item actions
│       ├── <Schema>CreateScreen.tsx      screen.create — field.* widgets grouped by x-ui-group, action.create, AgentPanelSlot, the `<schema>.screen.create.disclaimer` slot through help.inline (typescript/05 §4; empty by default), `dirty`
│       ├── <Schema>EditScreen.tsx        screen.edit   — likewise, with `<schema>.screen.edit.disclaimer`
│       └── <Schema><Op>Screen.generated.tsx   screen.custom stub per Tier 3 operation
├── application/                          application hooks (typescript/01 §3); no fetch, only the runtime's shared data hooks
│   ├── support.ts                        statusOf (404 → ready/empty, 403 → forbidden), messageOf, fieldErrors, serverFieldErrors, isDirty, versionedOf/etagFor (If-Match), useListState (query for useEntityList, viewQuery for useView)
│   └── <schema>/
│       ├── use<Schema>Actions.ts         <SCHEMA>_OPERATIONS, use<Schema>Capabilities(), one use<Schema><Op>(): MutationState<Body, Response> over useMutation per POST/PUT/PATCH/DELETE
│       └── use<Schema>Screens.ts         container hooks: use<Schema>ListScreen, use<View>GridScreen (both read `compact` from the runtime's useCompactLayout), use<Schema>DetailScreen, use<Schema>CreateScreen, use<Schema>EditScreen (both report `dirty`), use<Schema><Op>Screen
├── adapters/
│   ├── paths.ts                          `operations` and `paths` interfaces (method, path, params, body, response) + OPERATION_TABLE
│   └── client.ts                         createGeneratedClient(baseUrl, auth) = createClient<paths>(…)
├── registry.ts                           registerGenerated(registry): the generated screens only (key screen.*, schema, target = operationId, source 'generated')
├── setup.ts                              createGeneratedRegistry(): renderer registerDefaults(), then registerGenerated()
├── routes.tsx                            react-router RouteObject[]; containers pair a hook with the screen resolved through the registry (`useResolved('screen.<kind>', schema, operationId)`), so a whole-screen override replaces the default; lazy-free. The create and edit containers hold navigation while the form is dirty (runtime `useUnsavedChanges`), ask through the dialog resolved at `screen.custom` / `unsaved-changes`, and release the guard for the navigation after a save
├── nav.ts                                one entry per schema, ordered by schema name; `i18nKey` is typed so a frame renders `t(entry.i18nKey)` in the current locale
├── i18n.defaults.json, i18n.ts           <schema>.field.<f>.label|help|option.<v>|<member>.label, <schema>.screen.<kind>.title|disclaimer, <schema>.view.<v>.title, <schema>.action.<op>.label, <schema>.group.<g>.label, <schema>.nav.label, common.*; `t(key, vars?)` is the default text, `useT()` the provider-aware `t` every generated component and hook calls (typescript/05 §7), typed by `I18nKey`
├── index.ts                              barrel
└── manifest.json                         { buildVersion, source: { title, version }, files: [{ path, sha256 }] }
```

Routes: `/<schema>`, `/<schema>/new`, `/<schema>/:id`, `/<schema>/:id/edit`, `/views/<view>`,
`/<schema>/<op>` for a collection Tier 3 operation and `/<schema>/:id/<op>` for a record one.

Screens exist only when the matching operation is in the document with a non-empty capability
list. Screens compose resolved contract components: `useResolved<FieldProps<string>>('field.text',
'pet', 'name')` (the runtime's `useComponent(...).component`, typed by the caller); the registry
decides which renderer answers. Field widgets receive the renderer's value types (`text|select|
datetime → string`, `number → number | null`, `boolean`, `tags → string[]`, `subform → object`,
`reference → string | null`) and hand back `undefined` for an empty text or null, so zod reports a
missing required field as such; enum fields get `options` from `columns.ts`. Cells receive
`{ value, row, column }` with the column descriptor; state components `{ title, description?,
action? }` built by `stateProps` so an undefined member is never passed. The edit screen hands the
loaded document's ETag to the agent slot (`ifMatch`), without which an agent apply of an update or
delete fails closed. Actions are shown only
when `useCapability` grants every capability of the operation (the container filters them; a
missing capability is a hidden action). The posture (`x-ownership-posture`) chooses what a
missing read capability shows: `state.forbidden` under 403, `state.empty` under 404.

Conventions the document can override: a record operation (`get`, `create`, `update`) answers
with the Document type unless it declares a response schema; `delete` answers `void`; `list`,
`history` and custom operations are `unknown` without one. The id field is `entity_id`, else
`id`, else the first required Document property. History and bulk operations are typed in
`paths.ts` and the capability table but have no screen yet.

### Runtime contract assumed by the generated code

From `@star-board/runtime` (as exported, not as planned): `useEntity(schema, id)`,
`useEntityList(schema, q)`, `useView(view, q)` returning `{ data, loading, error, refetch }` with
`data: { items, total: number | null, page, pageSize }`; `ListQuery` is `{ page, pageSize, sort:
'name' | '-name', where }` and a view query is a flat record (`page`, `limit`, `sort`, one entry
per filter); `useMutation(operationId)` returning `{ mutate, mutateAsync, loading, error }` whose
variables are `{ id?, body?, doc? }` — update and delete pass `doc: versionedOf(entity)` and the
runtime builds `If-Match` from it; `useCapability(cap)`; `useComponent(key, schema, target)`
returning a `Registration` (the generated `useResolved` reads `.component`); `etagOf`,
`isHttpError`; `createClient<Paths>(baseUrl, auth)`; `createI18n(defaults)` with `.t(key, vars?)`
and `.has(key)`, `useI18n()`; `useUnsavedChanges(isDirty)` → `{ blocked, stay, leave, release }`;
`useCompactLayout()`. From the renderer named in `renderer`: the prop contracts above,
`AgentPanelProps`, `UnsavedChangesDialogProps` and `registerDefaults`. `test/stubs/*.d.ts` mirror these signatures (keep them in step with
`packages/runtime/src` and `packages/renderer-mui/src/contracts.ts`); the compile test proves the
output type-checks against them under `tsconfig.base.json`'s strictness, and
`examples/petstore-ui` type-checks the same output against the real packages.

### Platform rules applied (hexagonal-rules typescript/05)

- §4 regulated wording: each create and edit screen reads `<schema>.screen.<kind>.disclaimer`
  (an empty default) and renders it through `help.inline` at (`schema`, `operationId`) only when a
  translation table fills it; the wording comes from the reviewed source, never from code.
- §6 mobile: the table screens take `compact` (from `useCompactLayout` in the container) and render
  a card list of the first `COMPACT_CARD_COLUMNS` shown columns plus the open action, keeping the
  table's test ids under `data-layout="cards"`, so the same page objects drive both layouts.
- §7 i18n: every user-facing string in the emitted code is a `t(key)` call; `test/i18n-lint.test.ts`
  parses the output with the TypeScript compiler and fails on a JSX text node, a string literal in
  a JSX expression, or a literal given to a user-facing attribute or property.
- §9 shared primitives: the forms report `dirty`, the route containers wire the runtime's
  `useUnsavedChanges` and the renderer's dialog through the registry (no new contract key).

## Override model (typescript/12 §3)

`registry.ts` registers each generated screen at `(schema, operationId)` with `source:
'generated'`, and every route container resolves its screen through the registry. An override in
`src/features/<schema>/index.ts` registers at the same coordinates with `source: 'override'` and
wins (shared/01 §6a scoring, role for channel); a narrower override registers a field, column,
action or state component instead. `examples/petstore-ui/src/features/pet` holds one of each. The generator never reads or writes
`features/`: `writeFiles` refuses any path under it (`GENERATOR_OUT_OF_SURFACE`) and the override
safety test snapshots the tree before and after a run.

## Drift (shared/02 §1, `codegen:check`)

`check` regenerates from the document and diffs byte for byte against `out`; a hand edit is
`changed`, a deleted file `missing`, a stray file `extra`. The shared data hooks live in the
runtime and are never part of the check (contradiction #2).

## Tests

`pnpm -F @star-board/generator test`: golden snapshots (file list, plan, types, zod, hooks,
registry, routes, nav, i18n, manifest) in `test/__snapshots__/`; determinism; override safety;
drift; zod ⇄ schema agreement with fast-check (valid payloads accepted; `maxLength`, `enum`,
`required` and `additionalProperties: false` violations rejected); the generated-text lint
(`test/i18n-lint.test.ts`); and a compile test that type-checks the emitted tree with the
TypeScript compiler API against the stubs.

See the plan Part 2 and `.kiro/specs/06-generator/` for the owning spec.
